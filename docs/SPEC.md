# 入出力仕様

段と段のつなぎは、フォルダとファイルのルールだけです。レンダラーが何でも、このルールで出力すれば同じ流れで動きます。

```
[1 レンダリング]  何のツールでも可 (Three.js / V-Ray / Unreal ...)
      │  出力: <作業フォルダ>/images/*.png  +  <作業フォルダ>/sparse/0/{cameras,images}.txt
      ▼
[2 run.sh]        3DGS学習 + DZIタイル化 + サイト生成 を一括実行
      ▼
<作業フォルダ>/site/   静的サイト一式(サーバーに置くだけ)
```

## 1. レンダリングの出力ルール(入力)
| 項目 | 規約 |
|---|---|
| 画像 | `images/<カメラ名>.png`。8K想定、**全画像で同一サイズ・同一FOV**。jpg / tif / webp も可 |
| カメラ名 | 画像のファイル名(拡張子なし)。`images.txt` の NAME と一致させる。サブフォルダは付けない |
| カメラ情報 | COLMAPテキスト形式。`sparse/0/cameras.txt`(**PINHOLE**、全カメラ共通で1行)と `sparse/0/images.txt` |
| ポーズ | COLMAP規約。ワールド→カメラ(w2c)、クォータニオン(QW QX QY QZ)+平行移動、カメラ軸はOpenCV(+Zが前、+Yが下) |
| ワールド座標 | **Y-up**。ビューアーはこれを前提に方位角・仰角を計算する |
| 配置 | 被写体中心を向くオービット(半球など)。全カメラの光軸が1点(注視点)で交わること |
| 初期点群 | 任意。`sparse/0/points3D.txt`(学習の安定・高速化用。サイトには載らない) |

`tools/orbit-exporter.html`(Three.js)はこの形式で出力します。別のレンダラーを使うときは、カメラを上の形式で書き出すスクリプトだけ用意してください。`run.sh` とビューアーは変更不要です。

## 2. 出力(サイトの構成。すべて固定のファイル名)
```
site/
  index.html          # ビューアー(固定。編集しない)
  model.sog           # 3DGS (圧縮ツールが無い場合は model.ply)。ビューアーは .sog → .spz → .ply → .glb の順に探す
  sparse/0/cameras.txt, images.txt
  dzi/<カメラ名>.dzi + dzi/<カメラ名>_files/<level>/<col>_<row>.webp
  config.json         # ビューアーの設定(初期の視点・ズーム・3Dの上下反転など)。無いときだけ雛形が作られ、以後は手で編集する(run.sh は上書きしない)
```
差し替えるのは `images/` と `sparse/` だけです。`run.sh` を再実行すれば、変更分だけが再変換されます。

## 3. 中間ファイル(作業フォルダ/.build/)
`splat/splat.ply`(学習結果の非圧縮PLY。`keep_ply = no` ならSOG変換後に削除)、`train.params` / `sog.params`(前回の設定の記録)、`tiles.log`。消してもよい(次回は再学習になる)。

## 4. ビューアーの動作
- 移動中は3DGS、止めたら最寄りのカメラ位置へ移動して2D画像(DZI)に切り替わる。
- ズームは画角(FOV)のみ変更し、位置は動かない。2D側はDZIのディープズーム。
- 表示は短辺合わせのクロップ(画面のアスペクト比が違っても、長辺側が見切れるだけ)。
- `index.html?debug` でファイル選択UI(ローカルのGLB・PLY・フォルダを読む)が出る。通常は非表示。
